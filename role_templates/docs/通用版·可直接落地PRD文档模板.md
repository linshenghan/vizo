## 二、需求概述

### 1. 背景与问题

用 1-3 段说明为什么要做本需求，必须回答：

- 当前用户在什么场景下遇到什么问题
- 现有系统为什么不能满足
- 不解决会造成什么影响

### 2. 产品目标

| 目标类型 | 目标描述        | 衡量方式              |
| ---- | ----------- | ----------------- |
| 用户目标 | 用户完成什么事情更顺畅 | 可观察的用户行为或结果       |
| 业务目标 | 对产品或业务有什么价值 | 指标、效率、成本或质量变化     |
| 体验目标 | 体验上要改善什么    | 操作步骤、等待时间、错误理解成本等 |

### 3. 用户与场景

| 用户角色 | 触发场景 | 当前做法 | 期望结果 |
| ---- | ---- | ---- | ---- |
|      |      |      |      |

| 本期不做 |     |     |

## 十、PRD 自检清单

- [ ] 每个 P0 功能都有完整功能规格说明
- [ ] 每个功能都有入口、前置条件、规则、异常、文案和验收标准
- [ ] 所有用户可感知行为变更都进入“行为变更清单”
- [ ] RA §8 的边界场景全部有 PRD 决策
- [ ] AI 相关功能写清输入、输出、安全边界、结构化校验和失败降级
- [ ] 验收标准使用 Given / When / Then，且可被测试执行
- [ ] 没有把技术实现方案写成产品需求，技术细节留给架构设计
